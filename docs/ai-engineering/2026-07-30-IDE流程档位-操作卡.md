## 总原则

**默认直做（L0）。只有返工会贵过问答时才升档。升档用短计划或进仓文档，不默认整包方法论。**

```text
不确定性高  → 升档（防返工 > 问答税）
不确定性低  → 降档（问答税 > 防返工）
```

---

## 三档速查

| 档位 | 何时 | 你做什么 | Agent 必须产出 | 禁止 |
|------|------|----------|----------------|------|
| **L0 直做** | bug、按原型补页、已知契约小改 | 一句话说清目标与验收 | 改动 + 自验 | 先 brainstorm；再问已知决策 |
| **L1 短计划** | 半天以上、跨前后端、2–3 个技术分叉、初版切片 | 一轮确认方案 | ≤1 页：范围 / 切法 / 不做清单 → 再写 | 无限澄清；未确认就大改架构 |
| **L2 重流程** | 新产品方向、协议/领域模型重设计、多 Agent 大活 | 拍板关键分叉；要求写进仓库 | 需求/规格/计划进 `docs/` | 结论只留在聊天；无产物就开工 |

---

## 阶段默认（可例外）

| 阶段 | 默认 | 例外 |
|------|------|------|
| 产品设计 | **L2** | 文档/原型已齐 → 压成短确认 |
| 初版开发 | **L1** | 关键分叉未拍 → 升半档再决策一次 |
| 补页 / 修 bug / 小迭代 | **L0** | 越改越发散 → 停，升 L1 |

## 开场口令

**L0**

```text
按现有 docs/原型直接做。不要 brainstorm。做完自验并说明怎么验的。
```

**L1**

```text
先给一页方案：目标、切法、文件触点、不做清单、验收标准。我确认后再写代码。
```

**L2**

```text
先澄清关键分叉并写入 docs/（需求或规格）。聊天结论不算数，进仓才算数。确认后再进入 L1 计划。
```

---

## 升 / 降档信号

**升档**

- 同一问题被问第三次仍说不清
- 改 A 必须推倒 B/C
- 你开始犹豫「要不要重做协议」
- Agent 连续两轮产出方向飘

**降档**

- 答案已在 `docs/` 或上轮定案里
- 任务可一句话说完且验收清晰
- 你在复述已知决策给 Agent
- 流程在问你本来已拍板的事

---

## IDE Skill 怎么配

1. **默认**：关掉 Superpowers（或禁止其自动触发）
2. **L2 需要时**：手动点名 / 新开对话，用完即止
3. **自建 Skill**：只编码反复踩过的坑与验证步骤；触发要窄；必须允许「按现有 docs 直做」直通退出
4. **不写进 Skill**：通用软件工程教科书、每轮必问清单
