## 1. 定位

CI/CD 是 AI 工程化的**护栏**：防止提示词 / Skill / 接口契约在合并与发布时悄悄坏掉。  
它服务三层评测里的**代码层 + 功能层（mock）**；live LLM 与 Persona **不**默认绑在每次 PR 上。

---

## 2. 为何暂停前刻意不做

- 产品已封板，无持续合并压力  
- 08-05 已把「review/自检进 CI」列为尚未落地；优先完成的是方法沉淀而非流水线脚手架  
- 单人自用 + 手工部署（`deploy/` systemd/nginx）已够用  

**不是否定价值，是阶段不买票。**

---

## 3. 建议演进（重启后）

### 阶段 1 — 只上 CI（应先做）

触发：`pull_request` + `push` to `main`

| 步骤 | 命令意图 |
|------|----------|
| Web | `apps/web`：`npm ci && npm run build`（含类型检查） |
| API | `apps/api`：`uv sync && uv run pytest` |
| 可选 | Skill/路由契约冒烟；**仅 mock LLM** |

失败的 PR 不能进 `main`。

### 阶段 2 — 半自动 CD

- `main` CI 绿后：构建 `dist` + 部署 API（SSH / rsync / compose）  
- 部署后 `curl` health（及必要的 `/api` 探活）  
- 密钥仅 GitHub Secrets；**永不进仓**  
- Nginx：长超时；若有 SSE 则 `proxy_buffering off`（与既有部署经验一致）  

### 阶段 3 — 更像「AI 工程化」

- Skill / prompt 变更触发 mock 冒烟（可调用 `seed_three_themes_flow` 的 mock 模式）  
- 失败可回滚上一产物  
- live e2e、Persona：夜间 / 手动 / 发版前，不挡日常 PR  

---

## 4. 与部署形态的关系

已有路径：`deploy/nginx-host.conf`、`deploy/learning-api.service`，同域反代 `/` + `/api`。  

CI/CD 不强制改架构；Compose 与否是运维偏好。要点不变：

- `data/` 持久化与备份  
- 单 worker 更适 SQLite  
- 生产不用 `--reload`  

---

## 5. 验收口径（若实施）

| 项 | 标准 |
|----|------|
| CI | PR 必绿才能合并 |
| mock 冒烟 | 主路径无阻断（功能层） |
| CD | 探活通过；密钥未泄漏 |
| 非目标 | PR 上打 live DeepSeek；Persona 三人设每次必跑 |

---

## 6. 口令

**先 CI 护契约，再 CD 装机器。**  
**mock 进流水线，live 进发版仪式。**
