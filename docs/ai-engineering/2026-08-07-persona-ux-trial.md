## 2. 主路径结果（摘要）

三人共创 / 锁定 / 队列 / 展开 / 复盘均可走通。典型耗时：

| 步骤 | 耗时 |
|------|------|
| 阶梯 start | ~10–14s |
| 资料 start | ~12–14s |
| 资料多轮 | ~9–12s |
| 计划 start | ~10–12s |
| 计划多轮 | ~6–8s |
| 活动展开 | ~2.5s |
| 周复盘 | ~2.5–3.5s |

冷启动三段共创合计常要 **约 40–60 秒纯等待**（不含阅读与点选）。

一致现象：**锁定后 `today=0`，队列 5–10 条**（符合「开放队列 + 今日承诺」定案，但着陆文案/CTA 当前有坑，见 §3.1）。

学习槽满拦截文案清晰：`learning 槽位已满（1/1），当前占用：「…」`——但要到计划确认才爆，前面已付两次共创成本。

## 3. 真实建议（按严重度）

### P0 · 锁定着陆把「未承诺」说成「计划可能为空」

**证据：** `CreateSummaryPage` 在今日承诺为空时写「暂无今日任务（计划活动可能为空…）」；三人锁定后队列其实都有活动。

**伤害：** 用户以为共创失败/计划没生成，最伤信任的冷启动终点。

**建议（本 PR 已改一版）：**

- 文案改为区分「队列有货但未承诺」vs「真的没有活动」。
- 主 CTA 改为「按建议填入并开始今天」；次要「先回今日看板」。
- 仍遵守开放队列定案：不静默灌任务，但**首次锁定必须给显式一键填入**。

### P0 · 技术主题首屏资料仍偏官方（验证了真实反馈①）

**证据（p2）：**

- 首轮：`《Rust 程序设计》` / `Rust Book 官方教程` / `Rustlings`
- 用户明确「别再塞 The Book…要对照卡 + 编译错误病例」后，才变成对照卡 / 病例集 / 官方仅索引

**建议：**

- Skill2 / 资料共创对 `theme_type=tech` 设默认策展人格：**官方文档配额 ≤1，且角色=索引**；默认交付「AI 学习包」（对照卡、病例、最小例子）。
- 首轮就按此生成，不要等用户骂完再改。
- 与需求文档里「资料关改学习包」记账项对齐，建议升为下一迭代定案。

### P1 · 通识多轮约束经常不改清单（验证反馈②的变体）

**证据（p1 / p3）：** 要求「阅读脚本 / 只要 3 份实操 / 微信读书优先」后，书名列表基本不变；p3 甚至像在列疑似幻觉书名（如「AI产品评测：从入门到精通」）。

**建议：**

- 资料多轮若用户给出数量/形态约束，**必须**改 `resources` 与 `target_count`（后端 prompt 已有类似约束，模型仍常偷懒——需后处理校验或强制重写）。
- 通识默认交付物改为「本周阅读脚本 + 1 本主书」，而不是 3 本经典并列。
- 对无法检索到的书名降级或标注「待核验」，避免假权威。

### P1 · 学习期活动默认 10 条，碎片用户过载

**证据：** 三人 `learning_acts=10`；练习期还可到 8。每日 20–30 分钟用户会感到「队列很长、永远做不完」。

**建议：**

- 计划共创默认：学习期 **4–6** 条可检查活动；练习期按周而非堆 8 条细项。
- 或锁定后只把「本周切片」放进队列，其余折叠为计划书章节。

### P1 · 计划偏好服从不稳定

**证据：** p2 要求每天 45 分钟，多轮后 `daily_minutes` 仍 30；p3 要求 20 分钟则生效。

**建议：** 计划 prefs / 用户话术解析后做结构化覆盖（已有 `_apply_plan_prefs`），多轮 message 路径也要强制写回 `daily_minutes` 与 activities 粒度，而不是只靠模型自觉。

### P2 · 槽位拦截太晚

**证据：** 第二主题可走完阶梯+资料共创，到计划锁定才 409。

**建议：** 创建主题或进入计划共创前，若 learning 槽已满，走现有 `/create/intercept` 或计划页顶部硬提示，避免浪费两次 LLM。

### P2 · 冷启动等待税

三段串行各 10s+，无进度叙事时像卡死。

**建议：** 共创页明确「正在生成阶梯/资料/计划 · 约 15 秒」；可考虑资料与计划的预取，或把确认后的下一步 start 提前触发。

### P2 · 今日任务标题过长

例：`阅读《AI产品经理手册》评测框架章节，找出评测目的相关的定义和维度。`

通勤扫读困难（p3 诉求）。

**建议：** 列表标题 ≤ 18–24 字；细节进展开 / description。

### P3 · 周复盘可用，且能听见用户抱怨

复盘会吸收「跳转多」等答案并给出调整建议——说明复盘链路健康。可把「今日就地勾选」做成更硬的产品约束（需求已定着陆 B），避免复盘反复开出同一张处方。

## 4. 做得好的地方（别改坏）

1. **开放队列模型本身合理**：锁定不静默灌今日，避免内疚日历；首页「按建议填入今天」文案清楚。问题在锁定摘要页，不在模型。
2. **技术主题在强约束下能改过来**（p2 第二轮），说明 Skill 有潜力，缺的是默认策展。
3. **槽位文案具体到占用主题名**，可执行。
4. **活动展开**约 2.5s 出 3–4 步，颗粒度适合 30 分钟。
5. **零完成率防护**（复盘代码里对夸奖的 soft guard）方向正确。
