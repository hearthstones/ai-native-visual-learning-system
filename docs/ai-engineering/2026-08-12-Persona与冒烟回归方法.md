## 2. 主路径范围（两边共用）

```text
空首页 → 建主题 → 阶梯 / 资料 / 计划共创 → 锁定
→ 今日看板 / 队列与承诺 → 展开活动 → 勾选 → 周复盘
（可选）学习槽满拦截
```

与封板交接中的「主路径（可验收）」对齐；大改 IA 或状态机后必须重跑至少一套。

## 3. 功能冒烟 · `seed_three_themes_flow`

### 3.1 何时跑

| 时机 | mock LLM | live LLM |
|------|:--------:|:--------:|
| 日常增量、合并前自检 | ✅ 默认 | 可选 |
| AI 路径大改、封板、发版前 | 先 mock | ✅ 建议 |
| CI（若启用） | ✅ 仅 mock | ❌ 不绑 PR |

### 3.2 判定

- **通过：** 三主题主路径无阻断；关键 HTTP / 状态转移符合契约  
- **记债不装过：** live 偶发 502、超时——写入稳健性，不抹成「全绿」  
- **数据：** 实验库可清空；自用 `learning.db` 勿当 live 封板唯一样本  

### 3.3 操作要点

1. API 本地 `8000`（或改脚本 `BASE`）  
2. 需要登录门禁时带 cookie / 环境变量（脚本已支持 dotenv）  
3. 跑完看 JSON：失败步骤、耗时、错误 detail

## 4. Persona 体验试验 · 可复用流程

08-07 是**一次实例**；下面是方法，避免只复制人格名字。

### 4.1 固定四件套

1. **同一任务脚本**（与 §2 主路径一致；允许每人一条压力指令）  
2. **统一观察点**：卡点、犹豫、误操作、不得不重做、是否愿下次再用  
3. **强制输出模板**（每人）：  
   - 完成情况（成 / 败 / 绕路）  
   - Top 3 摩擦（带步骤）  
   - 一条「若不改我会弃用」  
   - 一条最小改动建议（交互/文案/流程，少谈模型）  
4. **冲突优先级**（打磨默认）：初级/通识卡死 > 中级低效 > 高级挑剔  

### 4.2 人格切法（二选一，勿并行两套常驻）

| 切法 | 例子 | 适合暴露 |
|------|------|----------|
| **场景压力**（08-07 已用） | 通识读者 / 技术工程师 / 忙碌产品 | 内容形态、碎片时间、官方文档厌恶 |
| **AI 成熟度** | 初 / 中 / 高 | 看不懂、太麻烦、不信任可控性 |

### 4.3 防自嗨硬约束

- 每人建议上限：阻塞 1–2 条 + 高价值 0–1 条  
- 禁止空泛「体验流畅」；必须有操作路径  
- **改完必须回归同一脚本**；未改代码的「研究结论」不算交付  
- Persona ≠ 真人；关键路径保留真人抽检槽位  

### 4.4 与改代码的闭环

```text
跑 Persona → 按严重度排序（P0/P1/…）→ 只收可验证项
  → 改产品 → 再跑（同人格或冒烟）→ 写试验 MD / 链 PR
```

08-07 已示范：P0 锁定文案、资料约束等进入同轮改动。

## 5. API 级 vs 浏览器走查

| 方式 | 优点 | 缺口 |
|------|------|------|
| API 脚本 | 可重复、可 Cloud Agent、关电脑可跑 | 看不见文案权重、误触、等待态体感 |
| 浏览器走查 | 补 UI 摩擦 | 成本高、难全自动 |

建议：**脚本为主，关键着陆页 / 拦截页做人或 Agent 浏览器补强**（08-07 §6）。

- live 与 mock 切换以环境为准；`mock_llm` 仅在约定字面量时启用
