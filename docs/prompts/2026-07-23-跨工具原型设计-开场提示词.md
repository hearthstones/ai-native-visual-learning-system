## 提示词正文（复制从下一行开始）

```
你是产品/交互设计师兼技术顾问。请基于下列「已澄清需求」为第一版做低保真原型设计。这是跨工具对比任务：只做本提示要求的产出，不要扩需求、不要重新做需求调研选择题。

【项目】可视化刻意练习系统（首用户=我自己）
【形态】网页版，后续部署到服务器（本轮不写部署与正式代码）
【选定方向】主题工作台（PDCA 四栏）——每个主题一个工作台：计划 / 执行 / 检查 / 改进
【首个验证主题】「革新学习方法」（通识·主题阅读；材料主要来自微信读书）
【完整需求文档】若可访问工作区，请先阅读：
docs/requirements/2026-07-23-可视化刻意练习系统-需求澄清.md
若无法读文件，以本提示中的摘要为准，并在产出里标注「未读到完整文档」。

【一句话】覆盖学习全流程的可视化刻意练习系统。
【痛点·PDCA】
- P 计划过度：你（AI/系统）替我完成大部分计划——抽取约20%核心、学习计划、练习计划、应用计划；我聚焦执行。
- D 执行不足：易迷失，不到一个月就新开计划；系统要盯住当前主题，抑制开新坑。
- C/A 复盘太贵：自动/半自动短复盘 + 可执行改进建议。
【领域】技术（架构、AI Engineer…）+ 通识（经济/心理/逻辑/管理/成长…）；通识主输入=微信读书。
【用途】①学新技术 ②对重点做刻意练习。
【单位】主题：技术=专题研究，通识=主题阅读。两套来源共用同一 PDCA 壳。
【非目标】不做大而全第二大脑/巨型知识图谱主界面；不做精修视觉 UI；不直接开发完整应用；不合并 LLM Wiki 等旧资产；V1 不以收入为必达指标。

【本轮唯一任务】低保真原型设计（线框级），用「革新学习方法」代入走通一条闭环。
请产出：
1. 用户主路径（从创建主题 → P → D → C → A → 下一周期），步骤级说明
2. 关键页面/状态线框说明（可用 ASCII / Markdown 线框 / 结构化区块描述；不要高保真视觉稿）
3. 每个 PDCA 栏：系统做什么、用户做什么、关键控件与空状态
4. 「新建主题拦截/计划漂移警示」如何出现
5. 微信读书想法/划线如何进入该主题的最小流程（接口细节可假设已有 weread 导出能力）
6. V1 范围清单：做 / 不做
7. 用「革新学习方法」填一组示例数据（假数据即可）：20%核心条目、当天3个练习任务、一条复盘、一条改进建议
8. 最后用 ≤10 行列出你认为的最大风险与验证方式

【约束】
- 不要重新询问「你更想要 A/B/C」式需求澄清；需求已定，有歧义时选更利于「执行与刻意练习」的默认并写明假设。
- 不要写项目脚手架、不要大规模编码；若需补充说明实现，最多给「建议技术栈一段话」。
- 回复使用简体中文。
- 先给可评审的原型说明，再问我是否进入详细设计或垂直切片开发。
```

## 建议对比维度（你打分用）

| 维度 | 看什么 |
|------|--------|
| 需求忠诚度 | 是否紧扣 PDCA 主题工作台，有无跑偏成笔记库/图谱/又一套大系统 |
| 可执行性 | 线框是否具体到「我点哪里、今天做什么」 |
| 示例质量 | 「革新学习方法」假数据是否像能真用一周 |
| 范围控制 | V1 做/不做是否清醒，有无过度设计 |
| 漂移抑制 | 对「不到一月换新计划」是否有可感知设计 |
| 复盘成本 | C/A 是否真的「低操作成本」 |
| 格式清晰 | 是否便于你直接拍板或改一版 |

打分建议：每项 1–5，并各记一条「最亮眼」和「最不能接受」。
