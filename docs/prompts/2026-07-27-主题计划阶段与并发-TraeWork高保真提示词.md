```
你是产品/交互设计师兼前端实现者。请为「可视化刻意练习系统」做「主题计划 · 阶段切换与并发」高保真 HTML 原型（不是线框、不是低保真说明稿）。

【背景矛盾】
- 学习/练习/应用三者独立维护 → 维护成本大于执行成本。
- 三者永远等权混在一份课表 → 忽视阶段比重与时长差（学可数日，练约月，用可达半年）。
- 已定解法：一份主题计划生命周期；用户手动切阶段；进入下一阶段 = 上一阶段计划归档只读 + 当前阶段计划新生成；练习/应用不追求精巧。
- 并发：全局硬拦「1 学习 + 3 练习 + 5 应用」；主焦点手设上限 3，超过 1 个时强警告并记入计划漂移。
- 反模式：三入口并排同等维护；九宫格写满才能晋级；用「主题未毕业」禁止一切新学。

【产品锚点】
- 主题工作台 PDCA；示例可用「革新学习方法」（学习期）+「矛盾论」（练习续跑）。

- 设计说明：docs/specs/2026-07-27-主题计划阶段与并发-design.md
- 总纲：docs/requirements/2026-07-23-可视化刻意练习系统-需求澄清.md

- 学习计划对话共创：prototype/pages/learning-plan-cocreate.html（可链接进入「当前学习切片」编辑，本轮不必重做整套共创对话）。
- 既有「学习计划 / 练习计划 / 应用计划」三入口并排：本轮应改为「当前阶段 + 当前切片 + 历史归档」模型，勿继续强化三份并列工程。

【本轮范围】
必须可感知演示：
1. 主题当前阶段展示；当前计划切片可编辑（清单级即可）；历史切片只读归档。
2. 「进入下一阶段」：学习→练习时，学习计划标完成归档，练习计划新生成（前端模拟生成即可，内容要短、糙）。
3. 阶段槽位指示：1/1 学、x/3 练、y/5 用；学习槽已满时再开学习期或再切进学习 → 硬拦 + 腾槽说明。
4. 主焦点：手设；设第 2 个主焦点 → 强警告 + 漂移事件可见；尝试第 4 个 → 硬顶。
5. 至少 2 个主题的示例数据，体现「一主学习 + 一练习续跑」。

可选：~~从 workbench P 栏链入本页~~（workbench **已删除**）；或在本页内嵌简化工作台壳。二选一写明。现应从 theme-overview / theme-work「计划」模式链入。

【交互硬约束】
- 阶段切换仅手动；不要自动按天数晋级。
- 满槽硬拦，不可静默突破。
- 当前可编辑的主要是 active 切片；completed 只读。
- 练习/应用切片：短清单，不要做成第二份 20 小时精课表。
- 支持手动改当前切片条目（增删改/勾选），整表重生最多作次要操作。
- 桌面优先；窄屏可堆叠。

3. 可感知交互（前端模拟）：切阶段归档+新生成；槽位硬拦；主焦点警告与漂移记录
4. ≤8 条关键假设 + 如何验证「用户愿意用阶段切换，而不是去开第三个并行学习计划」
```
