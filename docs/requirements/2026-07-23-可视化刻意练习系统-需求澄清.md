## 1. 一句话定义

覆盖学习全流程的**可视化刻意练习系统**。

它不是笔记仓库，也不是又一个大而全知识管理系统；核心是：以「主题」为基本单位，走完 **计划 → 执行 → 检查 → 改进（PDCA）**，并对重点做刻意练习。

---

## 2. 背景与澄清过程摘要

早期曾在两条产品思路间摇摆：

1. **通用型学习系统**：技术 + 通识，来源含网课与书籍；
2. **微信读书定制系统**：围绕每日约 30 分钟阅读。

澄清后收敛为：

- 产品身份应立在 **全流程 × 刻意练习 × 可视化 × AI 承担计划与复盘**；
- 通识侧仍以微信读书为主要输入；技术侧以专题研究进入同一套「主题」壳；
- 部署形态倾向 **网页版，部署到服务器**（具体功能以本文与后续设计为准）。

讨论中还触及更深层次原因（建系统替代行动、缺少外部反馈、身份/主线不清等）。它们有助于理解动机，但**本文以用户最终陈述的需求与 PDCA 痛点为准**，不把中途的选择题结论当作已定需求。

---

## 3. 痛点（按 PDCA）

### 3.1 Plan（计划过度）

- 现象：花大量精力做规划（找重点、排学习/练习/应用计划），挤占执行。
- 期望：系统（含 AI）替用户完成**大部分**计划工作，例如：
  - 找出约 **20% 核心内容**；
  - 生成 **学习计划**；
  - 生成 **练习计划**；
  - 生成 **应用计划**。
- 用户聚焦：**执行层面**。

### 3.2 Do（执行不足）

- 现象：执行中容易迷失；往往不到一个月就会**新开一个新计划/新主题**。
- 期望：系统帮助盯住**当前主题循环**，降低计划漂移与开新坑冲动，使力气花在执行与练习上。

### 3.3 Check / Act（检查与改进成本过高）

- 现象：复盘极其有用，但太耗时耗力，多数人（含本人）难以坚持。
- 期望：系统提供**低成本**的检查与改进建议（自动/半自动复盘 + 可执行的调整建议）。

---

## 4. 目标与非目标

### 4.1 目标

1. 以**主题**组织一次完整的学习 PDCA 循环。
2. AI 承担大部分 P 与大量 C/A；用户主要做 D（执行与刻意练习）。
3. 可视化呈现主题进度、核心掌握、练习/应用情况，以及计划漂移风险。
4. 覆盖两类领域与两种用途（见下节）。
5. 网页部署，可供自己稳定使用；首主题用真实主题验证闭环。

### 4.2 非目标（本阶段明确不做或后置）

- 不做大而全「第二大脑」或跨主题巨型知识图谱（主题内可有轻量核心清单）。
- 不在需求未定前扩展为 Freedom Engine / LLM Wiki 的替代品；与现有知识资产的深度合并后置。
- 不以「产出/收入」作为 V1 主指标（可作长期方向，不写入首版必达）。
- 不在 V1 同时做复杂双模式引擎（研究模式 / 阅读模式两套 UI）；技术和通识共用主题工作台壳，仅来源不同。

## 5. 领域、来源与用途

### 5.1 领域

| 类型 | 示例 | 主要来源（当前） |
|------|------|------------------|
| 技术领域 | 架构、AI Engineer 等 | 专题研究材料（课程、文档、论文、实践等，具体接入后续设计） |
| 通识领域 | 经济学、心理学、逻辑学、管理学、个人成长等 | **微信读书**（主题阅读） |

### 5.2 用途

1. **学习新技术**（进入技术类主题 / 专题研究）。
2. **针对重点做刻意练习**（主题内对 20% 核心反复练习与应用）。

## 6. 基本单位：主题

一次进入系统、从头跑完 PDCA 的基本单位是 **主题（Theme）**：

- **技术**：专题研究（例如某个技术方向或能力专题）。
- **通识**：主题阅读（多本书围绕同一主题）。

技术和通识共用同一套主题工作台；差异主要在输入来源与材料形态，不在 PDCA 结构。

### 6.1 锚定示例主题

**「革新学习方法」**（当前正在进行的主题阅读）——后续详细设计与首版验证应能代入该主题走通全流程。

## 7. 选定产品方向：主题工作台（PDCA 四栏）

每个主题 = 一个工作台，主界面围绕四栏（或等价的四阶段视图）：

| 阶段 | 系统职责 | 用户职责 |
|------|----------|----------|
| **P 计划** | 基于材料抽取约 20% 核心；生成学习 / 练习 / 应用计划 | 确认或小幅微调，不从零写计划 |
| **D 执行** | 每日（或每次）只推少量刻意练习任务；抑制未完成主题上随意新建 | 执行任务；阅读、练习、应用 |
| **C 检查** | 根据完成记录、笔记、练习结果等生成短复盘 | 低成本审阅结论 |
| **A 改进** | 给出下一周期计划调整建议（加深 / 砍掉 / 加密练习等） | 采纳或改一句 |

### 7.1 可视化（方向性，非界面定稿）

- 主题进度；
- 核心概念/要点掌握度；
- 练习与应用次数；
- 计划漂移警示（例如：当前主题未完成又要新建）。

### 7.2 主题内知识形态

- 采用**轻量核心清单**（对应「约 20% 核心」），挂学习材料与练习；
- **不以**完整概念地图作为主界面（避免再次陷入「完善地图替代执行」）。

### 7.3 输入（已澄清的约束）

- 通识主题：对接微信读书想法/划线等；本机已有 `weread-skills` 可作导入能力参考。
- 笔记与主题数据落在本系统；与 LLM Wiki / Study* 等现有资产的深度整合**本阶段不纳入**。

### 7.4 形态与部署

- **网页版**，部署到服务器。
- 具体技术栈、账号、权限、服务器环境：待详细设计。

## 8. 成功标准（需求层）

在「革新学习方法」或同类真实主题上，若以下成立，则需求方向被验证：

1. **计划负担明显下降**：用户很少从零写计划，主要是确认 AI 计划并执行。
2. **执行更稳**：同一主题能持续超过「不到一个月就换新计划」的旧模式（具体天数阈值可在设计阶段量化）。
3. **复盘可负担**：检查与改进以短周期、低操作成本完成，且能产出可执行调整。
4. **刻意练习可见**：重点（20% 核心）上有明确的练习/应用记录，而不只是阅读进度。

## 9. 待详细设计解决的问题（本澄清文档不关闭）

以下已识别；**定案进度不均**，打勾项见专题澄清，其余仍开放：

1. 主题的创建向导（材料如何进入、书单如何绑定微信读书）。→ **主路径已定案**：见 [2026-07-29 主题创建与冷启动共创 · 需求澄清](./2026-07-29-主题创建与冷启动共创-需求澄清.md)（信息 → 阶梯共创 → 资料共创 → 三阶段计划共创）。微信读书**真绑定 / API**与共创保真度仍开放。  
2. 「20% 核心」的生成与修订交互（人工标注重要度的规则）。→ 创建④计划文档中先以「核心精神」节出现；独立修订规则仍开放。  
3. 刻意练习任务的具体类型与判定「完成」的标准。  
4. 「应用」记录的最小字段（任意真实问题 vs 结构化模板）。  
5. 新建主题的拦截/冷却策略（如何硬/软阻止计划漂移）。→ **部分定案**：见 [2026-07-27 主题计划阶段与并发 · 需求澄清](./2026-07-27-主题计划阶段与并发-需求澄清.md)（阶段硬槽 1+3+5；主焦点 >1 记漂移）。练习/应用字段与每日配额等仍开放。  
6. 复盘触发频率（每日 / 每周 / 主题阶段门）与改进建议的形态。  
7. 技术类主题的材料接入方式（与微信读书对称的最小导入）。→ **方向已定**：与通识共用「资料共创」壳；字段差异与示例仍开放（见 2026-07-29 专题 §6）。  
8. 网页信息架构、权限（单用户即可或预留多用户）、数据存储与部署拓扑。→ **信息架构部分定案**：L1 今天+主题 / L2 主题看板 / L3 执行·计划·复盘（见 `docs/specs/2026-07-28-IA改版-三层信息架构交付.md`）。权限与存储仍开放。  
9. 与长期「产出/收入」目标的挂钩是否需要预留字段。

## 10. 结论

| 项 | 结论 |
|----|------|
| 产品 | 覆盖学习全流程的可视化刻意练习系统 |
| 组织单位 | 主题（技术=专题研究，通识=主题阅读） |
| 结构 | PDCA；AI 重 P/C/A，人重 D；界面组织演进为三层 IA（入口 / 主题看板 / 单模式作业） |
| 创建 | 信息表单 + 阶梯/资料/三阶段计划共创（见 2026-07-29 专题） |
| 首验主题 | 革新学习方法 |
| 通识输入 | 微信读书（创建期经资料共创限定/筛选；真接入仍开放） |
| 形态 | 网页，服务器部署 |
| 下一阶段 | 开放项继续专题澄清；已定案路径用规格/原型验证愿用性 |
