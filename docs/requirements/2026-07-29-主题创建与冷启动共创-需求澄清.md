## 1. 本专题解决什么

总纲 §9 留下「主题如何创建、材料如何进入、微信读书如何绑定」等开放项；IA 改版后回访用户能走 L1→L2→L3，但**新用户从零**仍断在「要共创先有主题、要有主题先共创」。

本专题澄清：

1. **建主题主路径**：从空态到「计划锁定并可执行」的步骤顺序与每步职责；  
2. **AI 共创在创建期怎么用**：阶梯 / 资料 / 计划各自回答什么问题，与十倍速学习 Skill1–3 的关系；  
3. **明确否定的做法**：把创建做成「材料来源单选 → 导入占位 → 核心预览」表单流水线。

信息架构三层（今天 / 主题看板 / 单模式作业）见 IA 交付；本专题只定**创建与冷启动**，不重开 IA。

---

## 2. 澄清过程（逐步看清）

需求分析在本轮是迭代出来的，不是一次拍板：

| 轮次 | 当时看法 | 后来发现 |
|------|----------|----------|
| IA 改版后 | 回访路径可点通即够 | 空态缺失；「新建」常进满槽拦截；共创挂在 L3，冷启动进不去 |
| 冷启动 v1 设计 | 表单四步：信息 → 材料来源 → 导入占位 → 核心预览 → 再进计划共创 | 原型验收否决：第 3、4 步迷惑；第 2 步不像「筛资料」，整段不像学习产品 |
| 用户纠正 | — | 正确心智是：**一次轻量表单 + 三次 AI 共创**（阶梯 → 资料 → 三阶段计划） |
| 原型 v2 + 愿用性体感 | 主轴语义对了 | 共创若只是静态剧本，用户「愿试用但不愿当真用」；锁定后的执行日叙事必须与冷启动 Day1 一致 |

结论：需求澄清要同时记**定案**与**否决项**，避免实现回流到已否定路径。

## 3. 决策结论

### 3.1 冷启动主路径（硬约束）

```text
① 主题信息（表单）
   主题名 · 类型（通识 / 技术）· 一句话目标（可选）
        ↓
② 学习阶梯（AI 对话共创）
   为当前主题生成难度台阶；用户选择「我现在在哪一级」并确认
        ↓
③ 学习资料（AI 对话共创）
   筛高杠杆资料；可限定范围（如微信读书 / 仅中文 / 专业向）
   支持多轮：加约束重筛、评估用户丢来的候选、否决低质噪声
        ↓
④ 学习计划（AI 对话共创）
   产出学 / 练 / 用三阶段计划骨架；收敛后显式锁定
        ↓
首次主题看板 → 进入执行（今日任务生效）
```

- ① 是**唯一**以表单为主的步骤。  
- ②③④ 必须是**左对话 / 右活文档**式共创，禁止再做成纯表单关卡。  
- 锁定前今日任务**不生效**；锁定后才进入可执行态。

### 3.2 两套「阶段」不得混名

| 用语 | 含义 | 出现位置 |
|------|------|----------|
| **学习阶梯级别** | Skill 式能力台阶（如 L1–L5）；用户点选「我在哪」 | 创建② |
| **主题生命周期阶段** | 学习期 → 练习期 → 应用期；槽位 1+3+5；手切 | 创建④ 计划结构；日常阶段管理 |

创建文案与导航须让用户分清：先回答「我水平在哪」，再回答「主题计划按学练用怎么排」。

### 3.3 与十倍速 Skill 的关系

| 创建步 | 能力来源 | 产品用法 |
|--------|----------|----------|
| ② 阶梯 | `ai-learning-step1-stage` | 拆台阶 + **用户确认当前级**；不是只读说明书 |
| ③ 资料 | `ai-learning-step2-resource` | 高杠杆清单 + 排序/短路径；通识可限微信读书 |
| ④ 计划 | `ai-learning-step3-plan` 精神 | 保留「约 20% 核心 + 可执行切片」；**课表形态服从本产品**：学/练/用三阶段，愿用性约 **30 分钟/天**，不把「10 节 × 2 小时」当唯一课表 |

冷启动允许强制顺序「阶梯 → 资料 → 计划」。回访用户从 L3「计划」进入时，**可单开某一共创**，不强制每次重跑三关。

### 3.4 资料共创的最小体验标准

用户要的不是「勾选来源」，而是像教练一样筛资料。至少要能：

1. 提出范围约束后重筛（例：只用微信读书）；  
2. 提交一条候选链接/书名并得到评估；  
3. 看到对低质内容（标题党、新闻级科普）的**否决与理由**。

真实微信读书 API / 全网检索可后接；需求层先定**交互职责**，不绑死实现。

### 3.5 空槽与满槽

- **学习槽空闲**：从 L1「新建」进入①，不进满槽拦截。  
- **学习槽已满（1/1）**：仍走既有拦截（推进 / 休眠 / 废弃腾槽），见阶段与并发专题。  
- 主题锁定并占学槽后，L1 不得再呈现「零主题空态」；应进入「已有主题的今天」。

### 3.6 明确否决（勿回流）

- ❌ 创建主路径做成：材料来源单选 → 导入占位 → 核心预览表单。  
- ❌ 把②③④塞进同一页问卷一次性填完。  
- ❌ 空槽用户默认进入「先腾出学习槽位」拦截。  
- ❌ 锁定后执行页叙事与创建期 Day1 / 切片不一致（破坏信任）。  
- ❌ 仅用静态剧本冒充共创，却在产品叙事上声称「你已完成定制」（原型演示可暂用剧本，需求成功标准仍要求**用户可注入约束并看到文档更新**）。

## 4. 成功标准（本专题）

1. 新用户能从空态不经满槽拦截，走完①→②→③→④锁定，并进入今日可执行任务。  
2. 用户能说清：刚完成的是阶梯定位、资料清单，还是三阶段计划。  
3. 资料步至少发生过一次「约束或否决」类交互，而不仅是展示书单。  
4. 阶梯步必须完成「当前级别」确认，才能进入资料。  
5. 锁定后「今天」与作业面的日期/任务与计划学习期切片一致（至少 Day1 叙事自洽）。  
6. 用户愿用性自测：愿意拿真实主题试建一次，且不因创建流程本身放弃。

---

## 5. 非目标（本专题不做）

- 不规定真实 LLM、微信读书、爬虫的技术选型。  
- 不在本专题重做完整复盘 / 阶段推进演示。  
- 不要求练习期 / 应用期在冷启动④达到与学习期同等详细度（可骨架 + 日后从 L3 再共创）。  
- 不关闭总纲中仍开放的：任务完成判定、应用记录字段、复盘频率等。

---

## 6. 仍开放（带入后续澄清 / 设计）

1. 共创多轮的**最小可操作保真度**（快捷约束 chip vs 自由输入 vs 真模型）。  
2. 通识「微信读书」从演示约束到真绑定的最小闭环。  
3. 技术主题资料共创与通识是否共用同一壳、字段差多少。  
4. 从 L3 单进计划共创时，与冷启动④的信息架构是否完全同一页。  
5. 「20% 核心」在④中是计划文档一节，还是锁定后单独可修订对象（总纲 §9.2 仍部分开放）。

---

## 7. 结论

| 项 | 结论 |
|----|------|
| 创建主路径 | 信息表单 → 阶梯共创 → 资料共创 → 三阶段计划共创 → 锁定执行 |
| 计划形态 | 与阶段专题一致：学 / 练 / 用；冷启动给出骨架 |
| 材料进入 | 资料共创（可限微信读书），非导入占位表单 |
| 水平定位 | 学习阶梯点选当前级（≠ 主题学练用阶段） |
| 否决 | v1 表单四步（来源 / 导入占位 / 核心预览） |
| 下一阶段 | 按成功标准收紧原型保真度；API 与字段细则另开 |
