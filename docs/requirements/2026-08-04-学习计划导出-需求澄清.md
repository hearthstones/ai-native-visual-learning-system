## 1. 本专题解决什么

系统当前默认路径是「建主题 → 共创 → 锁定 → 在系统内执行」。但真实场景里，很多人并不是要长期托管一段学习生活，而是**突然想学一件事**，需要一份能带走、能执行的计划。

本专题先澄清：

1. **导出是否成立**：学习计划是否应作为可脱离系统的产物（如 HTML）；  
2. **轻量用户心智**：与「完整学习系统」并行的另一条价值主张——一次性计划、用完即走；  
3. **与现有共创的关系**：导出是共创终点的可选出口，还是独立轻量入口。

---

## 2. 触发场景

| 要素 | 内容 |
|------|------|
| 人物 | 同事 |
| 目标 | 一周完成 Flutter 开发入门 |
| 过程 | 交给 AI Agent 生成学习计划 |
| 产物形态 | **HTML**（可读、可分享、可离线打开） |
| 观察 | 计划本身已够用；对方并未表现出「还要进一个学习系统」的需求 |

由此意识到：

> **大多数人其实并不需要一个学习系统**；更多是突然想学个东西，需要保持轻量化。

---

## 3. 产品判断（待验证）

| 判断 | 含义 | 风险 |
|------|------|------|
| 计划是交付物 | 共创收敛后，用户要的可能是「带走的计划」，不是「留下的账号与看板」 | 若只做系统内执行，会漏掉最大的轻量人群 |
| 轻量优先于完整闭环 | 对冲动型学习者，导出 / 单页计划的价值高于今日任务、阶段槽位、看板 | 过度轻量化会削弱刻意练习与长期主题管理的差异化 |
| 系统仍有其位 | 对愿意持续练、愿意回访的人，完整系统仍有意义 | 两条路径若混成一条，会既不轻也不深 |

初步立场（未定案）：**完整系统与可导出轻量计划可以并存**；导出不是系统的附属打印，而是承认「一次性学习」是主流入口心智。

---

## 4. 开放问题（下一轮澄清）

1. **导出时机**：仅「计划锁定后」可导出，还是共创过程中任意快照可导出？  
2. **导出形态**：HTML 是否为首选？是否还要 Markdown / PDF / 纯文本？  
3. **轻量入口**：是否存在「不建主题、不进看板，只共创一份计划并导出」的旁路？  
4. **与执行的关系**：导出后是否仍引导回系统执行，还是明确「导出即结束」？  
5. **内容范围**：导出仅计划骨架，还是含阶梯、资料清单、每日任务？  
6. **品牌与可编辑性**：导出页是只读成品，还是用户可在页内继续勾选 / 改期？

---

## 5. 明确不做（当前）

- 不因本灵感推翻现有主题 / 阶段 / 看板主路径。  
- 不在未澄清前把「导出」做成营销页式独立产品线。  
- 不假设所有用户都要轻量；只承认轻量是**更大基数的入口需求**。

---

## 6. 一句话备忘

突然想学 → 要一份能带走的计划（如 HTML）→ 多数人不需要留下一个学习系统；系统要有**轻量出口**，并可能需要**轻量入口**。
