## 1. 本专题解决什么

计划共创产出的活动清单作为**计划层**合格，但作为**任务层**偏粗：用户打开后仍不清楚「这条接下来怎么一步步做完」。

本专题定案：**不对整份计划静默拆任务**；当用户觉得**某一条**计划活动太粗时，显式点击，由 AI 为该条生成可长期复用的执行结构，并可对话或手改。

## 2. 澄清过程

| 轮次 | 看法 | 结论 |
|------|------|------|
| 体验反馈 | 计划层 OK，任务层粗 | 需要任务层可执行性 |
| 规则展开试做 | 切分 description + 凑满步骤 | 否决：像强行凑任务，信任差 |
| 方向选择 | 计划层保持；任务层展开；新老计划都覆盖 | 采纳分层，但交互未定 |
| 交互定案 | AI Native：显式点击 + 轻量交互；单位=单条计划 | 本专题 |
| 存储与入口 | 长期复用；阶段管理 + 作业面计划 Tab 两处入口 | 本专题 |

否决项：规则切分凑步、静默批量生成今日微任务、用完整三栏共创壳重做整份计划。

## 3. 决策结论

### 3.1 分层与职责

| 层 | 产物 | 谁写 | 本专题 |
|----|------|------|--------|
| 计划层 | 学/练/用活动清单（title / description） | 计划共创 | **不改** |
| 任务展开层（新） | 单条活动的执行结构 | 用户显式触发 AI + 可手改 | **本专题** |
| 今日推进 | 从 active 切片投影 DailyTask | 现有逻辑 | 若对应活动已展开，执行侧展示展开结构 |

### 3.2 触发与单位

- **触发**：显式点击「任务拆分」；**不**静默生成。  
- **单位**：单条计划活动（`Activity`），不是整份计划、也不是「今日全部任务」。  
- **何时出现按钮**：每条活动常驻「任务拆分」；已拆分时状态文案为「已拆分 · N 步」。  
- **入口（两处都有，执行面也保留）**：  
  1. L3 作业面 →「计划」Tab 中的切片活动行；  
  2. 阶段管理页（`/themes/:id/plan`）当前切片 checklist 行；  
  3. 作业面「执行」Tab 中对应今日任务也可进入调整。

### 3.3 生成结果（长期挂在该活动上）

真源：`Activity.execution_doc`（JSON），与 `title` / `description` 并存；**不**回写改粗计划文案（除非用户在手改里明确改标题——V1 不把手改范围扩到计划 title）。

| 字段 | 含义 | 约束 |
|------|------|------|
| `goal` | 这条要达成的目标 | 一句；禁止「每天/本周」套话当唯一内容 |
| `steps` | 可勾选步骤 | 2–4 条；动词+对象+范围；可在愿用时长内做完 |
| `resource_ref` | 资料绑定 | 优先指向主题 `resources_doc` 中的项；可空 |
| `outcome` | 完成标准 | 可检查的产出（笔记一句 / 划线 / 做 1 题等），禁止空洞态度句 |
| `minutes` | 预估分钟 | 默认对齐主题 `daily_minutes`（缺省 30） |
| `messages` | 本条展开的轻量对话历史 | 仅服务本条调整 |
| `updated_at` | 最近生成或修订时间 | ISO |

质量门槛（产品验收，写入 Skill）：

1. 去掉「每天/本周」后语句仍成立；  
2. 步骤互不重复，总时长贴合 `minutes`；  
3. 资料与步骤相关（有清单时尽量引用，不瞎编书名优先于乱绑）；  
4. 宁少勿假：不要为凑满三步而加「对照资料核对」「确认目标是否达成」类元步骤。

### 3.4 轻量交互

```text
点击「展开」
  → AI 基于：活动 title/description、主题目标、阶梯级别、资料清单、daily_minutes
  → 写入 execution_doc，打开轻量面板
        ↓
用户可：
  A. 直接使用（执行时勾选 steps）
  B. 手动改 goal / steps / outcome / minutes / resource_ref
  C. 在面板内短对话：「再具体」「只要阅读」「拆成今天能做完的」→ AI 更新同一 execution_doc
```

- **不是**完整左对话/右活文档共创壳；面板内嵌短对话即可。  
- **重新生成**：允许「再生成」覆盖结构；已勾选的 step 完成态——V1 简单策略：重生清空 step.done（提示用户）。  
- **删除展开**：V1 可提供「清除展开」，回到仅有粗计划；可选后置。

### 3.5 与今日执行的关系

- `DailyTask` 仍按现有规则从 Activity 投影（每天最多 N 条等）。  
- 若 `activity.execution_doc` 存在：作业面「执行」中对应任务展示展开后的 goal / steps / 资料 / 验收（勾选 step 写回 `execution_doc`，可与任务/活动完成态联动）。  
- 未展开的活动：保持现状（标题 + 描述勾选），不自动凑步骤。

### 3.6 新老计划

- 锁定后的既有 Activity 均可按需展开。  
- 无展开时行为与现在一致；有展开才增强执行面。

---

## 4. 明确不做（本轮）

- 不静默、不批量把整份计划拆成今日微任务。  
- 不用规则切分 description 冒充 AI 展开。  
- 不把单条展开做成完整共创三步之一。  
- 不在本轮做番茄钟 / 外链学习工具深度集成。  
- 不强制每条活动都必须展开才能勾选完成。

---

## 5. 验收标准

1. 阶段管理与作业面计划 Tab，每条活动可见「任务拆分」入口；未拆分与已拆分状态可区分。  
2. 点击后生成并持久化；刷新后仍在；已拆分后仍可手改、对话调整、再生成。  
3. 手改与短对话均可更新同一 `execution_doc`。  
4. 执行面：已拆分活动的今日任务能看到步骤并勾选，且仍有「任务拆分」入口。  
5. 生成结果抽样能通过 §3.3 质量门槛（人工抽检即可）。

---

## 6. 一句话

单条计划太粗时，用户点「任务拆分」，AI 为该条生成可长期复用的执行结构；之后仍可手改或对话调整；计划层保持粗，任务层按需变细。
