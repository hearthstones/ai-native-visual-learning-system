## 1. 真实反馈原文（原意保留）

以下三条为用户原意转述，讨论与实现均以此为准，不稀释：

1. **资料收集阶段，资料过于官方，特别是技术主题。**
2. **资料收集阶段，很多时候用户甚至不需要原始资料，而是需要 AI 加工后的资料。**
3. **L1、L2、L3 功能有重叠的地方，跳来跳去太耗费用户心智。**

## 3. 现状对照（讨论前共识）

### 3.1 三层设计意图（文档定案）

| 层 | 路由 | 回答的问题 | 刻意没有 |
|----|------|------------|----------|
| **L1 今天** | `/` | 今天干什么 / 进哪个主题 | 完整共创、完整阶段台、完整复盘表单 |
| **L2 主题看板** | `/themes/:id` | 这主题怎样、下一步 | 完整共创对话、完整复盘表单 |
| **L3 作业面** | `/themes/:id/work?mode=` | 专注一种操作 | 四栏等权、他模式全文常驻 |

易混命名（讨论时勿混）：
- **IA 三层** L1/L2/L3 = 今天 / 看板 / 作业
- **学习阶梯** Level 1–5 = 能力台阶（`current_ladder_level`）
- **主题 phase** = 学 / 练 / 用

### 3.2 用户实际主路径（实现）

```text
日常回访:
  L1 ──主题卡──► L2 ──「进入执行」──► L3 execute
  L1 ──今日承诺/任务──► L3 execute（可跳过 L2）
  L3 ←返回── L2 ←返回── L1；Rail「今天」回 L1

计划 / 复盘 / 计划书:
  入口分散在 L2 次要导航、L3 mode、壳层；完整表单在独立页
```

### 3.3 重叠与心智摩擦（对照反馈③）

| 用户意图 | 当前可碰的地方 | 摩擦 |
|----------|----------------|------|
| 今天干什么 / 勾选 | L1 今日承诺；亦可经 L2 看任务再进 L3 | 同一意图多入口 |
| 开始干这件事 | L1 直达 L3；或 L1→L2→L3 | L2 是否必经不清晰 |
| 看主题怎样了 | L2 看板；L3 也可能露出进度碎片 | 摘要职责不清 |
| 改计划 / 复盘 | L2 次要链、L3 plan/review、壳层 | 入口重复，完整内容又在别页 |
| 读锁定交付物 | L2「主题计划书」 | 与「进入执行」并列时易抢注意 |

**一句话诊断**：分层在文档里清楚，在路径上「同一动作多个门」；用户感知是跳转税，不是层次感。

## 4. L1/L2/L3 讨论用方案（未定案）

讨论时从下列方向中收敛，可组合；**本文件不预设赢家**。

### 方向 A · 保三层，砍重叠（最小改）

- **一个意图一个主入口**：今天只在 L1；进度只在 L2；动手只在 L3。
- L2 去掉可勾选/可执行交互，只留「进入执行」单一主 CTA + 计划书等次要出口。
- L1 任务默认直达 L3，不经 L2。
- 计划/复盘完整能力只从 L3 对应 mode 进入；L2 不再并列「复盘」入口（或仅只读摘要）。

### 方向 B · 日常两层，L2 降级（中改）

- 日常默认：**L1 ↔ L3**；L2 改为「主题设置 / 计划书 / 阶段」次要面，不挡主路径。
- 冷启动锁定后着陆改为 L1 或 L3，而不是默认进 L2。
- L2 仍保留路由，但首页主题卡可配置为直达 L3（或「上次离开的面」）。

### 方向 C · 合并表面（大改，慎开）

- 取消独立 L2 页，主题摘要折叠进 L1 主题卡展开或 L3 顶栏。
- 仅在需要时再评估；与既有 IA 交付、计划书挂点冲突大。

### 建议讨论顺序

1. 日常「打开 App → 开始干」理想路径是几步？（目标跳转次数）  
2. L2 必须回答的问题是否仍成立？若成立，是否允许零交互（纯摘要）？  
3. 计划 / 复盘 / 计划书 各自的**唯一**入口挂在哪？  
4. 冷启动结束后第一落点？  
5. 与「开放队列 + 今日承诺」如何衔接（承诺在 L1，执行在 L3）？
