## 2. 诚实问题（原意保留）

1. **系统挂着 AI Native，但内容生成实质只靠模型预训练**；未接 websearch、RAG、harness（多步工具循环）。资料共创外部源目前只有微信读书 enrichment + 预训练（与 2026-08-11 ①′ 同一裂缝，本次升格为产品身份问题）。
2. **若把 websearch / RAG / harness 都补上，差异化仍薄**：用户不如直接用已有 AI Agent；本系统相对 Agent 的可守优势主要是 **可视化** 与 **系统化（PDCA / 今日约束 / 刻意练习编排）**，不是「更会生成」。
3. **把接入模型换成接入 AI Agent（如 Codex CLI）只能部分缓解 ①**：Agent 常自带检索与工具循环，资料质量可能上去；但学习资料库、主题状态机、今日承诺、结构化落库仍归本系统。接 Agent 补的是工人，不是外壳；且会引入长任务、不可复现、成本与权限等新问题。产品叙事若变成「套了学习 UI 的 Agent」，护城河仍不成立。

---

## 3. 由此推出的结论（本轮承认）

| 结论 | 说明 |
|------|------|
| 卖点曾立错位 | 「AI Native / 共创生成」被抬成身份，实际是薄壳 LLM 调用 |
| 真需求若成立 | 应立在 **约束执行的可视化 PDCA**，AI 是可插拔工人 |
| 能力缺口真实 | 技术主题资料偏官方、缺活水——根因是未检索，不是 UI |
| 补 Agent ≠ 自动重生 | 不解决「系统为什么存在」；最多换更强工人 |
| 暂停理由 | 在身份未钉死前继续堆功能，是在伪需求上加速 |

## 4. 暂停范围

**停：**

- 新功能、新专题定案、资料策展 / 联网搜索 / Agent 接入实现
- 以「补齐 AI 能力」为名的继续迭代

**保留（只读资产）：**

- 已落地代码与数据模型
- 已定案需求 / 规格 / 功能清单（历史真源）
- 已记账未定案项（资料①②、①′ 等）——暂停期间不升格、不关闭

**允许（极窄）：**

- 文档勘误、本暂停决议的引用回写
- 个人若仍运行本地实例做自用，不视为恢复产品开发

---

## 5. 重启前必须先答清

1. 产品一句话是否改成：**可视化 PDCA / 刻意练习外壳**，而非「AI 生成学习内容」？
2. AI 层定位：继续薄 LLM、接 Agent、或完全外置——**身份不依赖哪一种**？
3. 相对直接使用通用 Agent，用户留下来的不可替代步骤是什么（今日承诺？主题状态？练习节奏？）？
4. 资料关要不要做：若要，检索/Agent 是补丁还是主叙事？

未书面回答以上四点，不得恢复功能排期。
